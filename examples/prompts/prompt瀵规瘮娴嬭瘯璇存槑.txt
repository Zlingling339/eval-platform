Prompt 对比测试怎么做（v1 vs v2）
============================================================

一、两版的差别
------------------------------------------------------------
v1-简洁直答
  只要求「输出最终答案」，明确禁止解释、禁止前缀、禁止代码块。
  适合：规则评分器（label_match / keyword_rule / format_rule）、
        需要压成本、需要稳定解析的场景。

v2-结构化审慎
  要求先在内部判断题型与硬约束，再按固定格式输出：
  分类题第一行标签、第二行「理由：」；其它题第一行答案、第二行「依据：」；
  信息不足时第一行必须是「信息不足」。
  适合：检验格式遵循、减少编造、让报告能区分「答错」和「不会」。

两版都不是「更好的 prompt」，只是不同的约束组合。
对比的目的不是选一个赢家，而是看这次改动动了哪个指标。

二、放进平台
------------------------------------------------------------
1) 启动平台：python server.py（默认 http://127.0.0.1:8765）
2) 另开终端：
     python tools/seed_prompts.py
   会把两版写进 product=standalone_model / stage=model。
   也可以手动在「准备评测 → Prompt 管理」里新建：
   产品选「独立模型评测（不关联产品）」，版本号填 v1-简洁直答 / v2-结构化审慎，
   模板内容从本目录两个 txt 复制。

三、跑对比
------------------------------------------------------------
1) 「开始评测 → 模型评测」
   - 被测模型：选「模型与API配置」里保存好的 target 角色卡（会自动带出模型名和地址）
     或手动填写模型名，地址与 Key 用「设置」页的配置。
   - 评测方式：独立模型评测（不需要产品）
   - 评测集：同一套题，两次必须完全相同
   - 评分器：同一套，两次必须完全相同（分类题用 label_match）
   - 每道题跑几遍：建议 3；只跑 1 遍的差异可能只是随机波动
   - Prompt 版本：第一次选 v1，第二次选 v2
   - 版本标签：填 prompt-v1 / prompt-v2，方便在版本记录里找
2) 「查看结果 → 版本记录」
   - 两行分别点「查看运行」「报告」
   - 用「对比两个版本」或运行对比，看指标差异与逐题翻转
   - 口径不一致（数据集内容、评分器、重复次数、scope、限条数）时后端会直接拒绝比较，
     不会给出看似可比、实际不可比的数字。

四、怎么读结果
------------------------------------------------------------
- 先看有没有口径警告：mock、共同用例太少（<20）、模式不同，都会让差异不可信。
- 分类题看 accuracy / precision / recall / F1 的变化，再看逐题翻转：
  哪几条从 pass 变 fail，是「格式没跟上」还是「真的判错」。
- v2 多出的「理由/依据」第二行，规则评分器只要能取到第一行标签就不影响判定；
  如果你的评分器是 llm_rubric，则会读到整段输出，理由本身也会被评。
- 成本与延迟：v2 输出更长，token 与耗时通常更高，报告里有逐条 tokens / latency。

五、边界（务必知道）
------------------------------------------------------------
- 本地 mock / 仿真只验证链路，不能用来得出 prompt 优劣结论。
- 样本量小（<30 条）时，几个百分点的差异没有统计意义。
- label_match 是二分类评分器：gold.label 只能是 positive/negative（或 true/false）。
  多分类请用 format_rule + 自定义字段，或 llm_rubric。
- 只有真实调用第三方 API 的结果，才能说明这个模型在这个 prompt 下的表现。
